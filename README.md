# 생산 지수 시뮬레이터

첨부된 농장주 PI 화면을 바탕으로 만든 모바일용 계산기입니다. PI 계산만 제공합니다.

첫 방문에는 현재 조건과 목표 PI 모두 빈칸으로 시작합니다. 입력값과 중량 단위는 자동 저장되어 다시 방문하면 복원됩니다. 현재 조건 네 가지를 입력하면 PI 계산과 기록 저장을 사용할 수 있고, 목표 PI는 필요값 비교에만 사용합니다. 기록을 불러오면 현재 조건과 마지막 입력값이 갱신됩니다.

- 현재 PI: (육성률 × 평체) ÷ (사육일령 × FCR) × 100
- 평체는 kg/g로 전환할 수 있고 입력 범위는 1~5kg(1,000~5,000g)입니다. PI 계산과 기록의 중량은 kg 기준으로 처리합니다.
- 사육일령의 입력 범위는 20~50일입니다. 목표 필요값도 이 범위 안에서 달성 가능한 값만 적용할 수 있습니다.
- 목표 PI에 필요한 평체·FCR·사육일령·육성률을 각각 역산합니다. 다른 세 항목은 고정합니다.
- 필요한 값을 누르면 해당 조건의 PI를 미리 보고, ‘적용’으로 현재 조건에 반영하거나 ‘닫기’로 돌아올 수 있습니다. 적용한 값은 마지막 입력값에도 자동 저장됩니다.
- 목표를 충족하도록 평체(0.001kg)·육성률(0.01%p)은 올림, FCR(0.001)·일령(0.01일)은 내림합니다.
- 예시: 98.9%, 1.75kg, 31.3일, FCR 1.45 → 현재 PI 381.3.
- 목표 400: 평체 1.836kg 이상 / FCR 1.382 이하 / 일령 29.84일 이하. 육성률만으로는 상한 103%에서 달성 불가입니다.
- 육성률은 우수 가산분이 포함된 값을 입력하며, 100%를 초과하는 값도 입력·저장할 수 있습니다. 목표 역산의 육성률 상한은 103%입니다.

## 기록

현재 조건의 PI·육성률·중량·일령·FCR·저장 시각을 최대 50개까지 localStorage에 저장합니다. 목표값은 기록에 포함하지 않으며, 조정값은 ‘적용’을 눌러 현재 조건에 반영한 후 저장합니다. 미리보기 중에도 ‘현재값 저장’은 실제 현재 조건을 저장합니다. 기록을 불러올 때 목표값은 유지합니다.

마지막 입력값 자동 저장(`poultry-pi.draft.v1`)과 ‘기록 저장’으로 남긴 이력(`poultry-pi.records.v1`)은 별도로 관리합니다.

기존 kg 입력값은 그대로 복원하며, 새 입력 범위를 벗어난 과거 기록도 보존합니다. 범위 밖의 과거 기록을 불러오면 현재 입력 범위에 맞게 수정한 후 새로 저장할 수 있습니다.

DB·로그인·가상 사용자 ID는 사용하지 않습니다. 기록은 서버로 전송되지 않고 기기·브라우저·사이트 주소 간 공유되지 않습니다. 브라우저 데이터를 삭제하면 기록도 삭제됩니다. 시각은 기기의 현지 시간으로 표시합니다.

## 개발 및 검증

Node.js 24 LTS를 사용합니다.

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

기본 포트는 개발 5173, 빌드 미리보기 4173입니다. 결과물은 dist/입니다.

## Vercel 배포

1. 변경 사항을 GitHub에 반영합니다.
2. Vercel에서 Add New → Project로 seongjiny/mini-apps를 가져옵니다.
3. Root Directory는 저장소 루트, Framework Preset은 Vite로 지정합니다.
4. Deploy를 누릅니다.

vercel.json에 npm ci / npm run build / dist 설정을 포함했습니다. 환경변수와 DB 설정은 필요하지 않습니다. 로컬 빌드 검증과 실제 Vercel 배포는 별개입니다.
